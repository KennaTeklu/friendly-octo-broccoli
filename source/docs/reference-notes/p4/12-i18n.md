# 12 — i18n (vocab ladders + Vocab engine + I18N language picker)

> Reference module: `reference/scripts/p4/12-i18n.js` (12,523 lines).
> Source line ranges in p4-core.js: L1158-13050 (vocab ladders data, `window.P4_VOCAB_LADDERS`), L13639-14026 (P4 VOCAB ENGINE IIFE), L18149-18366 (P4 I18N IIFE).
> Native counterparts: `core/Vocab.kt`, `assets/data/vocab_ladders.json`, `assets/data/langs.json`.

## A. File purpose
Owns the entire internationalization surface: the **vocab ladders data** (every key UI phrase mapped to 10 reading-level variants L1..L10, where L5 is the authored default), the **P4 VOCAB ENGINE** (applies the user-selected reading level to every registered UI phrase by walking the DOM and re-texting matching elements), and the **P4 I18N module** (language selection via Google-Translate-compatible phrasebook, phrasebook export/import).

## B. Public surface
- `window.P4_VOCAB_LADDERS` — large data table, ~2000 keys × 10 levels.
- `P4.Vocab.init()` — applies the user's reading level at boot.
- `P4.Vocab.applyLevel(level)` — re-texts every DOM element with a `data-vocab` attribute.
- `P4.Vocab.level()` — returns the current reading level (1-10).
- `P4.Vocab.setLevel(level)` — persists + re-applies.
- `P4.VocabLevels` — array of `{ id, name, blurb }` for the picker UI.
- `P4.I18N.init()` — wires the language picker.
- `P4.I18N.setLang(code)` — sets the UI language (uses Google Translate for non-English).
- `P4.LANGS` — supported languages registry.
- `P4.I18N.exportPhrasebook()` / `importPhrasebook(json)` — per-user custom phrase overrides.

## C. Dependencies
- `window.P4`, `P4.store`, `P4.SEC` (from `01-core.js`).
- `P4.toast`, `P4.debounce`.
- `P4.keys.vocab` (`p4_vocab`), `P4.keys.lang` (`p4_lang`), `P4.keys.phrases` (`p4_phrases_custom`).
- DOM elements with `data-vocab="key"` attribute.
- Google Translate (loaded via `<script>` in index.html when language != 'en').

## E. Patterns worth porting
- **10-level reading ladder**: every UI phrase has 10 variants from L1 (simplest) to L10 (most technical), with L5 being the authored default. The user picks a level and the entire UI re-texts in place.
- **DOM walk + re-text**: `P4.Vocab.applyLevel` walks every element with `data-vocab="key"`, looks up the ladder for that key, and sets `textContent` to the level-appropriate variant. No re-render needed.
- **Phrasebook overrides**: users can override any phrase with their own wording (`p4_phrases_custom` localStorage). The custom phrase wins over the ladder.

## E2. Deep patterns
- **L5 = authored default**: this invariant means a user at level 5 sees the exact strings the developer wrote. This is the "safe" baseline — if a ladder entry is missing L5, the system falls back to the key itself.
- **Google Translate interop**: when the user picks a non-English language, the page enables Google Translate via `?#googtrans(en|xx)`. The P4 vocab system stays in English; Google Translate handles the translation. The phrasebook is for users who want to override Google's translation.
- **Debounced re-apply**: when the user drags the level wheel, `P4.debounce(applyLevel, 200)` prevents the DOM walk from running on every pixel of drag.

## E3. Edge cases
- Ladder entry missing for a key → key itself is used as the text (graceful fallback).
- `data-vocab` element has no textContent (e.g. an input placeholder) → `applyLevel` also sets `placeholder` attribute.
- Custom phrase overrides a key → custom wins, ladder is skipped.
- Google Translate fails to load → UI stays in English, toast "Translation service unavailable".
- User switches language mid-session → all `data-vocab` elements are re-texted; Google Translate reloads.

## E4. UX decisions
| Decision | Value | Reason |
|---|---|---|
| Reading levels | 10 | Granular enough, not overwhelming |
| Default level | 5 (authored) | User sees what developer wrote |
| Level picker UI | 3D scroll wheel | Fun + tactile on mobile |
| Custom phrase overrides | per-user | Power users can reword anything |
| Non-English via Google Translate | true | Quick coverage of 100+ languages |

## H. Top 3 gaps to close
1. **Per-language ladder** — the vocab ladder is English-only. Native should provide per-language ladders (e.g. a Spanish L1..L10) so users in other languages get the same reading-level control.
2. **Custom phrase cloud sync** — the phrasebook is per-device. Add cloud sync so a user's customizations follow them across devices.
3. **Reading-level adaptive content** — currently only UI labels re-text. Long-form content (exercise instructions, tips) should also adapt: an L1 user sees shorter, simpler instructions; an L10 user sees the full technical detail.
