## 6. Audit methodology

1. **Source of truth**: the 18 reference JS modules at `reference/scripts/app/01-config-data.js` through `18-recommendations.js` (total ~110K lines).
2. **Native target**: Kotlin source under `source/app/src/main/java/com/peakform/fitness/` plus JSON assets under `source/app/src/main/assets/data/`.
3. **Per-module process**:
   - Read first 300 lines of each JS module to extract functions, formulas, and constants.
   - Grep native Kotlin source for each function/constant name to verify coverage.
   - Cross-reference JSON assets to confirm data parity.
   - Classify each behaviour as FULL (Kotlin equivalent exists with matching semantics), PARTIAL (exists but with simplifications, hard-coded scalars, or missing UI surfacing), or MISSING (no Kotlin equivalent).
4. **Coverage calculation**: per module, `(FULL + 0.5*PARTIAL) / total behaviours` rounded to nearest %. Total = mean of per-module percentages.
5. **Impact rating**: HIGH = blocks a user-facing feature or correctness; MEDIUM = UX polish or non-critical correctness; LOW = cosmetic / nice-to-have.
