# Architecture Audit — 2026-10

**Scope:** v2.0.0 (versionCode 30) — the "full foundation" batch (5A through 18).
**Auditor:** z.ai code (automated).
**Baseline:** Repo HEAD `056d2c5` (versionCode 21, v1.5.1) — Batch 4E shipped.

## Coverage: 86%

The audit covers 22 batch items, 50+ files touched, and 7 new test files.
Coverage is computed as:

  (shipped items / total items in batch) × 100
  = (19 / 22) × 100
  = 86.4%

The three items that pulled coverage below 100%:

1. **Workout.kt 1RM context block + banded input** — partial. The Workout
   screen now routes tuning through `TuningSheet` and the post-session flow
   through `PostSessionFeelSheet`, but the inline banded input (per-rep
   weight row) is still the legacy single-weight field. A v2.1 patch is
   planned.

2. **Progress.kt ComponentRadarWithComparison** — the radar renders, but the
   "with comparison" overlay (vs. last month) is a single overlay layer, not
   the multi-series comparison the design spec called for.

3. **Coach-led prescription block in Workout** — the CoachingEngine produces
   tips but the Workout screen surfaces them as a flat list, not the
   "prescription block" layout the design contract specified.

The remaining 19 items are shipped and tested.

## Storage boundary (final, v2.0.0)

```
GLOBAL ("p4_ls" SharedPrefs via ProPrefs)
  ├── p4_theme {mode, accent}      ← theme mode (system/dark/light) + accent id
  ├── p4_dynamic                    ← Material You flag
  ├── p4_active_profile             ← active profile id
  ├── p4_default_profile            ← cold-start profile id
  ├── deviceId                      ← device UUID
  ├── p4_v22_migrated               ← one-shot migration flag
  └── consent log                   ← legal record (per-app)

PER-PROFILE ("p4_ls_<profileId>" SharedPrefs via ProfileState / ProfileSettings)
  ├── p4_onboarded / p4_ob_draft / p4_ob_finished_at / p4_first_launch
```
