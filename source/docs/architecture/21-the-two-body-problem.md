# 21 - The two-body problem

Many users train with someone. Partner, friend, gym buddy. Their sessions are coupled: same time, same gym, different bodies.

## The problem

Two users, one session. Their needs differ. Their progression differs. Their motivation is entangled.

Current models treat one user at a time. The coupling is invisible.

## What changes when a partner is present

- **Session structure** must accommodate both users in the same time window
- **Equipment** must be shared. The coach must schedule both to the same rack, same bench, same dumbbells
- **Rest periods** interleave. One lifts while the other rests
- **Motivation** is coupled. One user's drop can pull the other's
- **Comparison** is unavoidable. Both see each other lift

## What the two-body coach does

When two users are coupled:

1. Read both dossiers.
2. Read both arcs and both intents.
3. Build a session that alternates.
4. Schedule equipment use to avoid conflicts.
5. Note when one user is having a bad day, and adjust without shaming.
6. Never let one user's intensity dictate the other's.

## What the two-body coach never does

- Never forces symmetry. Two users are two users.
- Never compares. No leaderboards, no "who is ahead."
- Never shames. If one user needs a light day, the other trains on.
- Never leaks. One user's private data is not visible to the other unless consented.

## Storage

A CoupledSession entry references both user profiles. Both users must consent. Either can decouple at any time.

## When the coupling ends

When one user stops training with the other, both coaches are notified. Neither user is told why. The coupling ends cleanly.
