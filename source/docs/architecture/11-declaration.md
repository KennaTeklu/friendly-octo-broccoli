# 11 - The declaration pattern

Clarity before tuning. Every exercise card declares intent first.

## The wrong sequence

Coach decides -> User tunes -> Coach obeys.

Backwards. The user cannot tune what they have not seen. If the coach has decided, the user's tuning is a guess.

## The right sequence

Coach declares -> User reads -> User consents OR tunes.

The declaration is the missing piece. Before any numbers, before any tune icon, the coach says in one sentence what this exercise is about to do for this body.

"Back squat today: 4x5 at 82%. Over the next 6 weeks of Build, this makes your glutes and quads stronger. Your last three RPE were 8.5. We push today."

## The card structure

| Row | Content |
|---|---|
| Title | Exercise name |
| Chips | 11 components plus muscles |
| Declaration | One sentence from the coach |
| Prescription | Sets, reps, load, rest |
| Actions | Coach, go / Change |

## The tune icon

Not the primary action. The declaration is. The tune icon appears only when the user disagrees.

## The tuning dialogue

When the user taps Change, the tune sheet opens pre-populated with what the coach already decided. The user tunes from knowledge, not from a blank form.

## The preview

The tune sheet shows a preview of what the coach will do before the user saves.

"Coach will set today's deadlift to 4x5 at 80%, rest 3 min. Focus: back strength, hamstring maintenance."

If the user cannot see the coach's response before saving, it is a settings form, not a conversation.

## Why

The declaration makes the whole system legible. Without it, tuning is a guess. With it, tuning is a decision.
