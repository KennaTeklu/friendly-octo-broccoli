# 24 - Exit

Every relationship ends. The system must know how.

## The graceful exit

When a user leaves Pro — for a competitor, for a human coach, for life without tracking, for health — the exit is a scene. It is designed. Not a delete button.

## The last chronicle

On exit, the coach writes one final entry.

Not a summary. A closing paragraph, in the same voice, addressed to the user.

- What we did together
- What we learned
- What I wish for them
- Where to find what they built

The entry is signed by the coach. It is the user's to keep.

## What the user takes

Everything.

- Full export of the record: state tree, chronicle, sessions, PRs, tuning intents, philosophy
- The export contract is documented and stable
- The export is signed by the user's identity key
- The user can import the export into a new installation of Pro, or into a different system if one supports the format

## What is left behind

Nothing in the app. The profile is cleared after the export is verified and the user confirms. The identity key is the user's, held in their own keystore. It does not stay with the app.

## What the coach does after the user leaves

Nothing. No retargeting. No "we miss you." No emails. The relationship ended because the user ended it.

## The philosophy

A user who leaves with grace may come back. A user who leaves in anger will not. The exit is designed to make the first possible and the second impossible.

## The measure

A user who leaves and later says "Pro was the best thing I ever did for my training" — even without returning. That is success.
